# TreeCut v13 架构与问题解决总报告

## 最终结论

v13 已采用“新房迁移”方案：旧版不再作为正式运行入口，可验证的能力被迁移到一条清晰生产链。核心不是把旧代码改个名字，而是重新建立路径层、模型层、素材层、分析层、决策层、生产层、质量层和界面/API 层。

正式链路为：素材登记 → 真模型分析 → 风险筛选 → 卖点匹配 → 时间线规划 → 配音/字幕/音乐 → MP4/剪映草稿 → 质量回读 → 用户反馈。

## 已解决的问题

| 原问题 | v13 的处理 | 验证结果 |
|---|---|---|
| 文件、缓存和模型散落，依赖固定盘符 | 统一运行路径和环境变量，支持按安装位置重定位 | 干净副本 24/24 深度检查通过 |
| 旧分析器、调度器重复 | 正式入口只使用 ProductionService 和正式分析队列 | 61 项自动测试通过 |
| 模型存在但没有接入 | Florence、SenseVoice、YOLO、离线 TTS 已真实调用 | 真实视频分析及生成成功 |
| Qwen 在低显存机器可能爆显存 | 设为至少 10GB 可用显存才启用，失败回退 Florence | 配置和权重读取通过；等待台式机 GPU 验收 |
| Whisper 空目录冒充模型 | 必须有权重、配置和依赖才显示可用 | 当前明确为未提供，不进入正式链路 |
| CLIP、BGE-M3 计划与现实混杂 | 降为未来可选增强，不再作为核心成功条件 | 核心匹配不依赖它们 |
| 在线配音不稳定 | 增加本地 Sherpa-ONNX TTS | 离线中文配音真实生成 |
| 素材盘拔出或盘符变化 | 保存磁盘身份、在线状态和原路径，支持重新关联 | 离线模拟与恢复测试通过 |
| “抽 0 帧也算成功”等假测试 | 成功必须有真实帧、模型结果或明确失败证据 | 真实分析任务成功，失败不冒充成功 |
| 质量中心只做规则模拟 | FFprobe、完整解码、音量和字幕像素证据回读 | 真实项目 17 项质量证据通过 |
| 自动学习只是宣传空架子 | 改为可追溯的保留/替换/永久禁用反馈 | 数据库、API、桌面按钮均验证 |
| 只能生成剪映草稿 | 同时支持 MP4、草稿或双输出 | 四车道 4/4 成功 |
| 一个任务失败拖垮后续任务 | 队列隔离并持久化任务状态 | 成功→失败→成功测试通过 |
| 拔盘/崩溃后任务假运行 | 启动时把遗留运行任务标为中断，可一键重试 | 重启恢复测试通过 |
| API 或桌面入口与正式链路不一致 | 两者统一调用同一服务 | 桌面和本地 API 均实际启动 |
| 安装包暗中依赖 C 盘 Python | 携带独立 Python、DLL 和依赖 | 新副本 base_prefix 指向自身 G 盘 runtime |

## 现在的模块边界

- `platform`：能力探测、路径和硬件策略。
- `catalog`：素材来源、视频元数据、在线/离线状态。
- `models`：Florence、Qwen、SenseVoice、Whisper、YOLO 和 TTS 适配器。
- `analysis`：抽帧、语音、视觉、检测、风险和分类的正式工作器。
- `matching/planning`：可解释选材和时间线安排。
- `production`：统一生成 MP4、配音、字幕、音乐和剪映草稿。
- `quality`：对真实输出回读并保存证据。
- `feedback`：保存明确用户判断并用于后续匹配。
- `desktop/api`：普通用户界面和本机自动化入口。

## 仍需在真实业务中继续验证的事项

1. 把干净版复制回带 NVIDIA 显卡的台式机，完成 Qwen3-VL 的速度、显存和输出质量验收。
2. 使用岛台展示、生产、安装、口播、案例、空间展示六类大规模素材，建立分类准确率和错选率基准。
3. 用不同版本剪映打开草稿，确认版本兼容性。
4. 根据实际审美反馈调整镜头节奏、转场、音乐风格和卖点权重。
5. 在积累足够反馈后，再评估 CLIP/BGE-M3 是否能带来可测量提升；没有提升就不加入核心版。

## 不能夸大的部分

v13 已不是空架子，也不是假运行：模型推理、视频生成、草稿、质量回读和任务恢复都有真实证据。但它仍是经过工程化整理的可用开发版，不等于已经完成所有电脑、所有素材和所有剪映版本的商业级验收。尤其是 Qwen GPU 路线只能在目标显卡电脑上完成最后确认。
