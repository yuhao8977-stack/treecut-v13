# 升级任务 11：YOLO 物体证据接入决策

## 原问题

YOLO 会真实加载模型并输出英文物体标签、置信度和框坐标，但结果只写进分析 JSON。分类、风险、匹配和选材均不读取它，因此属于“运行真实、功能旁路”的半无效模块。

## 本次接入

1. 只接受置信度不低于 0.45 的物体作为业务证据。
2. 把烤箱、水槽、冰箱、餐桌、椅子、沙发等通用物体转换为可解释的中文检索词。
3. 室内家具和厨电可以在文件名、视觉模型均无法分类时，提供较低优先级的 `interior_space` 支持分类。
4. 强文件名业务用途继续优先。例如“客户案例”不会因为画面中有餐桌而被改成室内展示。
5. 物体词进入素材匹配，匹配结果明确标注证据来源 `objects`，权重低于语音和视觉描述。
6. 置信度不低于 0.85 的手机或电脑提供屏幕复核提示，并进入最终 `selection` 风险原因。
7. 低置信度物体完全不参与决策。

## 真实抽样后收紧的规则

16 张真实代表帧中，12 张检测到至少一个物体。检测到了烤箱、椅子、餐桌、人物、电视等，证明模型和正向链路真实可用。

真实抽样同时证明不能直接套用宽松规则：

- 画面中出现人物不等于人物口播。因此人物只提供“人物”描述，不自动分类为口播，也不提供“口播”检索词。
- 普通室内电视不等于敏感屏幕。因此电视不触发人工复核；只有高置信度手机或电脑提供复核提示。
- 第一张真实岛台画面没有检测结果，系统如实保留空证据，没有伪造模型能力。

## 结果结构

`objects` 现在除原始 `detections` 外还保存：

- `accepted_labels`
- `business_terms`
- `category` 与 `confidence`
- `needs_review` 与 `review_reasons`
- `rule_version=object_business_v1`

分类结果同时记录视觉分类和物体支持分类，方便以后追溯为何得到某个业务分类。

## 分析版本

分析管线版本从 `13.3.0` 升级为 `13.4.0`。旧分析结果没有物体业务证据，不能冒充新版本完成结果。正式库 32 条旧结果已保留，但状态已变为待重新分析；重新分析完成后才会成为 13.4.0 的正式候选素材。

## 测试隔离补漏

版本升级时发现 API 自动测试会初始化正式数据库。本次已经把每个 API 测试的数据、日志和任务数据库隔离到 G 盘临时目录，并在测试结束时关闭日志句柄。复测确认正式 `materials.db` 修改时间完全不变。

## 验证结果

- 真实 YOLO：16 张抽样，12 张有真实检测结果。
- 低置信度过滤、屏幕复核、强文件名优先、人物/电视防误判、物体匹配证据测试均通过。
- 全套自动测试：101 项全部通过。
- 正式数据库结果保留：32/32。
- C 盘仍不保存 Ultralytics 配置。

## 能力边界

YOLOv8n 使用通用 COCO 类别，不认识“岛台、岩板、抽屉、伸缩机构”等定制业务物体。它现在是辅助证据，不是岛台专用视觉模型。后续若要识别这些部件，需要专门标注数据并训练业务检测模型，不能靠标签映射假装实现。
