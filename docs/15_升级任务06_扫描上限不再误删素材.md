# 升级任务 06：扫描上限不再误判素材丢失

## 要解决的问题

旧扫描器达到 `max_files` 后只跳出当前目录的文件循环，随后继续遍历其他目录。最终又使用不完整的 `seen` 集合执行丢失对账，可能把没有机会访问到的有效素材标为 unavailable。

## 完成内容

- 扫描上限必须大于 0，否则立即拒绝。
- 上限只统计真正支持的媒体文件，不把无关文件占用媒体名额。
- 达到上限后立即停止整个目录遍历，不再只跳出一层循环。
- `ScanResult` 新增 `stopped_early` 明确信号。
- 达到上限不再算作 errors。
- 不完整扫描绝不执行 missing 对账。
- 不完整扫描不覆盖素材源上一次完整的 `file_count`。
- 桌面界面明确提示“达到扫描上限，本次未执行丢失素材对账”。
- 只有完整扫描结束后，才允许把确实不存在的文件标为 unavailable。

## 验收结果

- 新增 2 项扫描边界测试。
- 建立 3 个在线素材后，以 `max_files=1` 再扫描：
  - `stopped_early=True`
  - `total=1`
  - `missing=0`
  - `errors=0`
  - 数据库在线素材仍为 3
  - 素材源完整 file_count 仍为 3
- `max_files=0` 明确拒绝。
- 原有完整扫描删除文件后标记 missing 的测试继续通过。
- 素材库定向测试 14/14 通过。
- 全量自动测试由 81 项增加到 83 项，83/83 通过。

## 影响

这个修复主要保护未来的超大共享盘、移动硬盘和数十万文件素材库。扫描可以因为上限安全停止，但不能因此破坏已经建立的素材库知识。
