# 升级任务 13：模型完整性与真实加载验证

## 原问题

旧能力检测只检查极少数文件：Florence 只看一个权重，SenseVoice 只看 `model.pt`，YOLO 只看文件名，Qwen 只数两个分片。配置损坏、分词器缺失、Qwen 索引声明的分片缺失、只有 133 字节的空 ONNX 壳等情况可能显示为“就绪”。

## 新的四层状态

每个模型现在分别显示：

1. `files_complete`：关键文件、合理最小大小、关键 JSON 和索引完整。
2. `runtime_compatible`：当前便携 Python 是否有对应依赖，CUDA 模型是否有 CUDA 版 Torch 和 NVIDIA 硬件。
3. `ready`：文件完整并且当前运行时兼容。
4. `load_verified`：当前这组模型文件是否已经进行真实构造/推理验证。

“文件完整”不再等同于“当前电脑能运行”，“能运行”也不再等同于“已经真实加载验证”。

## 文件合同

- Florence：权重、配置、预处理器、分词器和自定义模型/处理代码。
- Qwen3-VL：配置、预处理器、分词器、权重索引，以及索引声明的全部分片。
- SenseVoice：权重、配置、BPE 模型和归一化参数。
- Faster-Whisper：`model.bin` 和配置，且要求本地运行依赖。
- YOLO：合理大小的权重和 Ultralytics 运行依赖。
- Chinese-CLIP/BGE-M3：配置与合理大小的 Safetensors 权重。
- 本地 TTS：选取最大的真实 ONNX 权重，并要求 tokens、lexicon 和 Sherpa-ONNX。

关键 JSON 必须能解析为对象；仅用空格或乱码填满到规定大小不能通过。

## 验证凭证

真实推理成功后，软件在 G 盘保存 `runtime_data/model_verification.json`。凭证绑定模型目录的相对文件名、文件大小和修改时间签名。文件发生变化后，旧的 `load_verified` 自动失效，必须重新验证。

该签名用于检测普通复制、替换和更新，不是下载来源的密码学签名；真正可信的最终安装包仍需发布清单提供 SHA-256。

## 真实烟雾推理

- Florence：真实图片描述成功，返回 415 字符。
- YOLO：真实图片检测成功，返回 10 个检测框。
- SenseVoice：自带中文样例转写成功，模型权重显示全部键匹配，输出 14 字。
- 本地 TTS：生成 42,434 字节 WAV。

候选便携版也使用自己的模型副本和自己的运行时独立验证：四项全部成功，TTS 生成 37,724 字节 WAV，总耗时约 246.8 秒。候选版没有复制主版本验证凭证，只有独立推理结束后才写入自己的凭证。

SenseVoice 日志虽然显示模型中心提示，但实际权重路径明确为 `G:\TreeCut_v13\models\SenseVoiceSmall\model.pt`，没有下载权重。

## 测试结果

- 空模型壳、过小权重、Qwen 索引缺片、CPU 运行时不兼容、凭证失效均有自动测试。
- 全套自动测试：109 项全部通过。
- 测试前后正式素材数据库没有变化。
- C 盘不保存模型和 Ultralytics 配置。

## 后续方向

发布阶段应生成整包 SHA-256 文件清单并在安装后校验；CPU 与 NVIDIA 运行时必须拆分，不能继续用当前 CPU 版 Torch 宣称 Qwen 可运行。
