# 升级任务 03：测试素材与正式制作隔离

## 要解决的问题

旧正式请求、API 和桌面界面默认都允许 `include_test_materials=True`。只要素材库中存在测试源，测试视频就可能进入客户成片。

## 完成内容

- `CreativeRequest` 默认值改为 False。
- API 请求默认值改为 False。
- Windows 桌面界面固定以正式模式提交，不再硬编码 True。
- 正式模式手工传入 True 会立即抛出明确权限错误。
- API 对该行为真实返回 HTTP 403，不创建后台任务。
- 只有环境变量 `TREECUT_DEVELOPMENT_MODE=1` 时才允许测试素材。
- API 启动脚本增加显式 `-DevelopmentMode` 开关；普通启动不继承开发模式。
- 四车道和故障隔离脚本明确声明自己需要测试素材，避免开发意图隐含在默认值中。

## 验收结果

- 新增 4 项正式/开发隔离测试。
- API 真实请求测试确认正式模式返回 403。
- 全量自动测试由 68 项增加到 72 项，72/72 通过。
- 正常用户不需要理解该开关：双击普通启动文件就是正式隔离模式。

## 额外发现

FastAPI 测试客户端显示 `httpx` 接口弃用警告。它不影响本任务功能，但证明当前运行时依赖需要在后续“重建锁定环境”任务中统一版本，不能继续手工拼接。
