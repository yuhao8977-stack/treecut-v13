# TreeCut 审计澄清报告（AUDIT_CLARIFICATION）

> 日期: 2026-08-25

## 澄清 1：assets=22465 vs media_files=28096，谁是 Canonical？

**结论：`assets` 是素材主实体（Canonical）；`media_files` 是文件实体，存在多对一关系。**

实证数据：

| 项 | 值 |
|---|---|
| assets | 22465（asset_id 主键，每素材一行） |
| media_files | 28096 |
| media_files 无 assets 关联 | **5631**（image 4782 + audio 3 + 其他未收录） |
| assets 无 media_files 关联 | 0 |

**解读：**
- `media_files` 收录了**全部发现的文件**（含图片 4782、音频 3），共 28096；其中 **23311 个是视频** → 这些被建为 assets
- 5631 个非视频文件（主要是图片）**没有**进入 assets 主库（P1 设计：仅视频建资产）
- `asset_types` 分布佐证：UNKNOWN 16289 + SEMI_FINISHED 6159 + FINISHED 17 = 22465
- **Canonical 关系**：assets.media_id → media_files.id，22465 条 asset 全部有有效 media_files 关联（无悬挂）

**修正原报告**：assets=22465 是"视频素材"数；media_files=28096 是"磁盘文件发现数"（含图片）。两者口径不同，不冲突。

## 澄清 2：content_classification=140 vs content_value=22465

**结论：content_value 对全部 22465 素材评分，但其中 22325 条无认知分类，按兜底基准计算。**

实证数据：

| 项 | 值 |
|---|---|
| content_classification（有认知分类） | 140 |
| content_value（有价值评分） | 22465 |
| 有 value 无 classification | **22325** |
| 有 value 有 classification | 140 |

**解读：**
- 140 条认知分类 = 100 条测试集 + 40 条补充（brain 分析过的）
- 其余 **22325 条评分时的 content_type = ""**（无分类），value.py 中 `TYPE_BASE[""] = 30` → 基准分按 30 计算
- 这些素材的评分**仅靠 ASR/OCR 关键词命中**，无内容类型锚定
- 这正是原报告"遗留问题"中提到的：**全量素材仅 140 条有认知分析**，价值评分对 22325 条是"低置信兜底分"

**修正原报告**：应明确写"22465 条评分中，仅 140 条有认知分类锚定，22325 条为无分类兜底评分"。

## 澄清 3：scene_semantics=4986，为什么不是 22465？

**结论：scene_semantics 仅覆盖 141 个素材（0.63%），且是"语义标注"不是"场景切分"。**

实证数据：

| 项 | 值 |
|---|---|
| scene_semantics 总行 | 4986 |
| 覆盖 asset 数 | **141** |
| 覆盖率 | **0.63%** |
| brain-industry-v1 行 | 4554 |
| clip-vit-base-patch32 行 | 432 |

**解读：**
- scene_semantics 是**认知语义标注表**（不是每个素材的场景检测结果）
- 4554 行来自 brain 行业分析（约 140 素材 × 多语义条目）
- 432 行来自 CLIP 视觉补认知（空镜素材）
- **场景切分（SceneDetector）的真实结果在 `segments` 表（41814 行），与 scene_semantics 是两回事**

**修正原报告**：scene_semantics 覆盖率 0.63%（141/22465），不代表场景检测覆盖率；场景检测覆盖率应在 segments/asset_processing_state(scene: DONE=22462/22465) 维度统计。

## 澄清 4：ocr_text=289218，覆盖多少 asset？

**结论：OCR 覆盖 13846 个素材（61.63%），行数≠素材数（一素材多帧多行）。**

实证数据：

| 项 | 值 |
|---|---|
| ocr_text 行 | 289218 |
| 覆盖 asset 数 | **13846** |
| 覆盖率 | **61.63%** |
| transcripts（ASR）行 | 51516 |
| ASR 覆盖 asset | **16168** |

**解读：**
- OCR 是按"帧"存储的：一素材可能数十帧各有 OCR 行 → 行数远大于素材数
- 13846 个素材有 OCR（≈每素材平均 20.9 帧 OCR）
- **OCR 覆盖率 61.63%**，ASR 覆盖率 71.96%——均未到 100%
- 缺口原因：纯空镜/无字幕视频无 OCR 文本、部分素材 OCR 竞态跳过（历史 SKIPPED 89）

**修正原报告**：OCR 覆盖率应写 61.63%（13846/22465），不是用 289218 行数表述覆盖率。

## 澄清 6：价值评分相关系数 0.631 / 分级一致率 90% 的样本基数

**结论：基于 20 条（human_business>0 且有价值分）——是 20，不是 71 或 100。**

实证数据：

| 项 | 值 |
|---|---|
| accuracy_review 总数 | 100 |
| human_scene != ''（内容确认） | 71 |
| human_business > 0（商业评分） | **20** |
| 相关性计算样本（商业>0 且有 value） | **20** |

**解读：**
- **0.631 / 90% 两个指标全部基于 20 条**有商业评分的素材
- 71 条内容确认（场景/产品/材质/功能/类型）**不参与**相关系数计算——那些维度的一致率是独立指标
- 20 条样本的相关系数**统计显著性弱**（n=20，r=0.631 的 p 值约 0.003，尚显著但置信区间宽）
- **修正原报告**：必须明确标注"相关系数基于 20 条人工商业评分样本"，不能暗示 100 条

## 澄清 7："22465 素材全量分析 0 失败" vs 130 损坏素材

**结论：是"系统任务 0 失败"（历史表述错误）；实际有 13 个素材 ASR/视觉任务失败，且 probe 状态全为 pending。**

实证数据：

**analysis_tasks 状态（任务粒度）：**
| 任务 | completed | failed | pending | skipped |
|---|---|---|---|---|
| asr | 10351 | **13** | 6 | - |
| vision | 10346 | **13** | 8 | 4 |
| ocr | 3975 | 0 | 6383 | 2 |

**asset_processing_state（素材×阶段粒度）：**
| 阶段 | DONE | FAILED | SKIPPED | PROCESSING |
|---|---|---|---|---|
| asr | 22446 | **13** | 4 | 2 |
| scene | 22462 | 0 | 0 | 3 |
| keyframe | 22376 | **13** | 75 | 1 |
| ocr | 15988 | 0 | 89 | 2 |
| duplicate | 22465 | 0 | 0 | 0 |

**broken_assets（13 条）原因：**
- 11 条：`asr: [Errno 1094995529] Invalid data found`（音频流解码失败——损坏/无有效音轨文件）
- 2 条：`asr: tuple index out of range`（whisper 输出异常）

**probe_status：全部 22465 条 = pending**（探测未执行或未更新，历史遗留字段）

**解读：**
- **正确口径**：22465 素材中 **22452 素材主流程成功（99.94%）**，**13 素材 ASR 失败**（音频损坏），0 素材 scene/duplicate 失败
- **"0 失败"是错误表述**——原报告误用了早期 P2/P3 阶段"0 失败"结论（当时 ~6480 素材阶段），或混淆了"系统无崩溃"与"素材无失败"
- OCR 有 **6383 pending**（历史 OCR 重跑未完成，WAL 竞态导致部分任务滞留）——OCR 覆盖率 61.63% 正是因此
- 130 与 13 的差异：130 是早期 BROKEN_ASSET_REPORT 中"疑似损坏"清单的规模，最终确认入库 broken_assets 为 13
