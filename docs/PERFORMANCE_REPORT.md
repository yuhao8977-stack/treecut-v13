# P2.5 性能基准报告

- **日期**：2026-08-22
- **测试环境**：临时库（复制生产 schema，不触碰生产数据）+ 生产素材真实路径
- **测试内容**：scene + keyframe 阶段（视觉分析），1 Worker vs 3 Worker
- **硬件**：6 核 12 线程 / 32GB / RTX 3050 6GB（本次未用 GPU，ASR 未参与）

---

## 1. 测试方法

1. 从生产库 `materials.db` **只读复制 schema** 到临时库（`runtime_data/temp/p25_bench/`）
2. 插入 3 个真实素材（生产库中 scene+keyframe 已 DONE 的资产，路径与生产完全一致）
3. 串行：`Worker25.run()` 单进程顺序处理
4. 并行：`WorkerPool(workers=3)` 3 个 spawn 进程各领 1 个任务
5. 对比耗时、结果一致性、是否有重复处理

## 2. 结果

| 指标 | 串行 1 Worker | 并行 3 Worker |
|---|---|---|
| 处理素材数 | 3 | 3（每 Worker 1 个） |
| 总耗时 | 36.5 s | 24.9 s |
| 吞吐 | 0.08 素材/s | 0.12 素材/s |
| **加速比** | — | **1.47×** |
| segments 产出 | 4 | 4（一致 ✅） |
| keyframes 产出 | 12 | 12（一致 ✅） |
| 失败/跳过 | 0 | 0 |
| 重复处理 | 0 | **0（原子领取生效）** |

## 3. 分析

### 3.1 为什么加速比只有 1.47×（而非 3×）

- **素材量太少**：仅 3 个素材、3 个 Worker，每个 Worker 只处理 1 个任务，任务间无流水线重叠；实际生产中每 Worker 连续处理成百上千任务，启动开销被摊薄
- **单素材时间差异**：3 个视频时长不同（10-40MB），最慢的 Worker 决定总时长（23.5s），快的 Worker 完成即空闲
- **视觉阶段本身是 CPU/IO 密集**：PySceneDetect 抽帧 + cv2 关键帧，单素材 8-20s 属正常；whisper ASR 未参与（benchmark 仅视觉阶段，避免与生产进程抢内存）

### 3.2 真实场景预期（ASR 加入后）

- 生产 P2 实测：单 Worker 处理 22,465 素材，前 12,000 个约 4.3 小时/万 → **~0.65 素材/s 全阶段（含 ASR）**
- P2.5 3 Worker 分片（视觉/ASR/OCR 各 1）预计：
  - 视觉与 OCR 远快于 ASR（ASR 是瓶颈，CPU whisper 单条数分钟）
  - **理想加速 2-3×**（视觉/OCR 并行 + ASR 独立）；若 ASR 占 70% 时间，则上限约 2.3×
  - GPU 化 ASR（RTX 3050）后 ASR 提速 3-5×，总吞吐再翻倍

### 3.3 并发正确性验证（关键）

| 检查项 | 结果 |
|---|---|
| 3 Worker 同时领取 | 每 Worker 恰好 1 任务，**无双领**（BEGIN IMMEDIATE 原子领取） |
| 结果一致性 | segments=4, keyframes=12 与串行完全一致 |
| 状态机 | 全部 completed，无 PROCESSING 残留 |
| 崩溃恢复 | 单元测试验证 recover_stale 可回收失联任务 |

## 4. 与旧 P2 单 Worker 对比（生产实测数据）

| 指标 | 旧 P2（单 Worker，PID 19152） | P2.5 预期（3 Worker） |
|---|---|---|
| 吞吐（全阶段） | ~0.65 素材/s | 1.3-1.9 素材/s（2-3×） |
| 1000 素材耗时 | ~25 分钟 | 8-13 分钟 |
| 剩余 10,451 素材 | ~4.5 小时 | 1.5-2.5 小时 |
| GPU | 未用 | 预留（默认 CPU） |

## 5. 结论

- ✅ **P2.5 并行调度正确性验证通过**：多 Worker 并发无重复领取、结果一致
- ✅ 3 Worker 已见 1.47× 加速（素材量小，保守值）；生产大任务量下预计 2-3×
- ⚠️ **瓶颈明确为 ASR（whisper CPU）**：后续若需更大吞吐，优先 GPU 化 ASR（预留 `--device cuda` 参数）
- 📌 本次基准**未触碰生产数据**（临时库 + 只读复制 schema），生产 PID 19152 全程不受影响
