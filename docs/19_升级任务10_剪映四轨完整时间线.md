# 升级任务 10：剪映四轨完整时间线

## 原问题

旧生成器虽然创建“主画面、配音、背景音乐、字幕”四条轨道，但存在以下不完整情况：

- 配音短于成片时，配音轨提前结束。
- 背景音乐短于成片时只播放一遍，后半段没有音乐。
- 返回值无条件声明存在配音和音乐，没有从真实草稿回读。
- 质量检查只要求至少三条轨道和一个视频素材，空配音、空音乐、空字幕、错误素材引用和越界片段都可能通过。

## 本次修复

1. 配音长于视频继续执行严格拒绝，禁止静默截断。
2. 配音短于视频时，用 FFmpeg 生成与项目等长的时间线音频，原声音结束后补静音。
3. 背景音乐生成与项目等长的循环时间线音频，并保持 0.10 音量及淡入淡出。
4. 时间线音频保存在草稿自身的 `treecut_assets` 目录，草稿不会依赖临时缓存。
5. `DraftResult` 从写盘后重新读取的真实轨道片段计算，不再无条件报告成功。
6. 字幕仍采用严格边界规则；任何字幕越过项目结尾都会拒绝生成，不进行无提示裁切。

## 新的严格草稿检查

质量中心现在验证：

- 三个必需草稿文件存在且 JSON 合法。
- 项目时长正确。
- 四条唯一命名轨道存在，类型分别为视频、音频、音频、文本。
- 四条轨道均有真实片段。
- 每个片段的素材 ID 可以在素材表中找到。
- 所有视频和音频源文件真实存在。
- 源时间范围不超过素材时长。
- 目标时间范围不超过项目时长。
- 主画面、配音和背景音乐从 0 连续覆盖到项目结尾。
- 元数据中的草稿 ID、时长与草稿内容一致。

## 真实验证

复用已验证的真实 5 秒、3 段视频计划重新生成剪映草稿：

- 主画面：3 段，连续覆盖 0–5 秒。
- 配音：1 段，补静音后连续覆盖 0–5 秒，音量 1.0。
- 背景音乐：1 段，循环后连续覆盖 0–5 秒，音量 0.10。
- 字幕：1 段，覆盖真实配音内容的 0–2.159 秒。
- 严格草稿质量检查：12 项全部通过。
- 全套自动测试：95 项全部通过。

## 尚未等同于人工打开验收的部分

结构和素材引用已经达到可机器验证程度，但不同剪映版本可能修改私有草稿格式。正式安装版仍需要建立至少两台电脑、多个剪映版本的“真实打开、预览、继续编辑”兼容性验收表；机器检查不能冒充剪映界面人工验收。
