# 升级任务 17：重复素材去重与制作前可读性检查

## 问题

素材库虽然计算了内容指纹，但成片规划只按数据库编号去重。同一个视频复制到两个目录后会有两个编号，可能在同一成片重复出现。素材扫描后若被拔盘、删除或失去权限，旧代码要到 FFmpeg 渲染时才失败。

## 修复

- 候选素材、匹配结果和最终镜头计划都携带快速内容指纹。
- 规划器同时按 `media_id` 和内容指纹去重；同内容不同路径默认只使用一次。
- 制作候选加载阶段重新检查素材是普通文件并实际读取一个字节；失效文件不进入模型匹配。
- SQLite 候选查询改用上下文管理器，保证连接及时关闭。
- 生产报告保留每个镜头的内容指纹，便于追溯为什么被去重。

## 验证

新增“两个路径、同一指纹只能生成一个镜头”测试。主版本 117 项自动测试全部通过。

这里使用的是首尾快速指纹，适合素材去重，不冒充发布文件的完整 SHA-256；发布完整性会在发布清单任务中单独解决。
