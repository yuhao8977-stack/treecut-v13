## 2. 任务表重复详情

**重复原因**：P2.5 调度器的 `sync_from_state` 多次运行 + `UNIQUE(asset_id, task_type)` 约束缺失，导致每次同步重复插入任务。

| 指标 | 数值 |
|---|---|
| 去重前总任务 | 155,345 |
| 重复 (asset_id, task_type) 组 | 30,527 |
| 重复多余行 | **124,239（80%）** |
| 去重后总任务 | **31,108**（唯一组合） |

**重复分布**：vision 10,288 组 / asr 10,287 组 / ocr 9,952 组（三类各约 1 万）

**去重规则**：
- 每组保留 `created_time` 最早 + `task_id` 最小的一条
- **跳过 processing 状态**（正在执行的不能删）
- 只操作 `analysis_tasks` 表，不影响其他表

**验证**：去重后 31,108 任务 = asr 10,351 + ocr 10,360 + vision 10,346（每类唯一），仅剩 2 组 processing 重复（正确保留）。

## 3. 素材内容重复详情

**assets 层**：`fingerprint_quick`/`fingerprint_full` 均无重复 → **每个内容只有一个 asset_id**（AssetsManager 已按指纹合并，设计正确）。

**media_files 层**：2,836 组指纹重复（如 `IMG_0724.JPG` 同时出现在"【254】客户目录"和"产品图"目录）——同一文件被扫描登记多次，但共享同一 asset，**不产生重复资产**。

**验证**：784 个重复指纹组中，0 组映射到多个 asset → 内容层面无真重复。

## 4. OCR 补跑任务恢复

去重时发现：OCR 补跑创建的 pending 任务被误删（保留了旧的 completed 任务），导致 9,062 个 NEW 资产无任务。已修复：
- 将这些资产的 OCR 任务从 completed **重置为 pending**（9,062 个）
- OCR 补跑已重启

## 5. 后续建议

1. **加 UNIQUE 约束**（防复发）：`CREATE UNIQUE INDEX idx_tasks_unique ON analysis_tasks(asset_id, task_type)`（需先清理残留重复，当前已清）
2. **可选 P3 重复识别**：运行 `--p3-run` 填充 duplicate_groups（内容级重复组），供素材库去重展示
3. media_files 冗余记录可清理（保留每个指纹一条），但当前不影响分析
