# 升级任务 12：CPU 多帧风险覆盖与中文规则

## 原问题

分析器会抽取视频约 10%、50%、90% 三个位置的画面，但在无 NVIDIA 显卡的电脑上只把中间一帧交给 Florence。开头或结尾出现的聊天界面、交易记录、无关截图等无法被发现。

旧风险词还把单独的 `bank`、`account`、`balance`、`calendar` 视为风险。英文描述中的 `a bank of kitchen cabinets`（成排橱柜）可能被误判为银行内容。

## 本次修复

1. CPU 环境也分析首、中、尾全部三张抽样帧。
2. CPU 使用逐张推理：一张完成后释放临时对象并执行垃圾回收，再处理下一张，避免三张图片同时形成模型批次。
3. CUDA 环境继续一次批量处理全部抽样帧，利用显卡吞吐。
4. 请求三张必须返回三条非空描述；少一条都禁止保存为完整分析。
5. 每条描述保存对应图片路径、视频时间点和文本，形成 `caption_evidence` 可审计证据。
6. 结果保存 `frame_strategy`，明确记录是 CPU 逐帧还是 CUDA 批量策略。
7. 分类和风险判断使用全部帧描述汇总，不再只看代表帧；代表帧文字仍保留给简洁展示和旧接口兼容。

## 风险规则收紧

删除容易误报的单词级规则，改用含义明确的短语：

- 英文：screenshot、screen recording、mobile phone screen、bank account、account balance、transaction record、payment details、credit card 等。
- 中文：截图、录屏、手机界面、聊天界面、银行账户、银行卡、账户余额、交易记录、交易明细、支付页面、付款码、收款码、身份证、手机号码等。

普通厨房、日历装饰、游戏屏幕和“成排橱柜”不会仅凭宽泛单词触发风险。

## 真实 Florence 验证

使用同一真实视频的首、中、尾三帧，在当前 CPU 笔记本上运行本地 Florence-2：

- 返回描述：3/3。
- 总推理耗时：55.138 秒。
- 识别内容包括人物、客厅、厨房、岛台、水槽、台面和游戏屏幕。
- 汇总分类：`interior_space`，置信度 0.65。
- 普通游戏屏幕未被误判为敏感内容。
- 模型与缓存均来自 G 盘，全程无需网络模型。

## 分析版本

分析管线版本升级为 `13.5.0`。13.4.0 及更早结果没有完整的 CPU 三帧风险证据，不能标记为当前完成结果。当前正式库本来已处于待重分析状态，因此没有再次丢失或覆盖结果。

## 验证结果

- 首中尾逐帧调用测试：通过。
- CUDA 全帧批量调用测试：通过。
- 部分返回禁止保存测试：通过。
- 中文敏感短语测试：通过。
- “bank of cabinets” 防误报测试：通过。
- 全套自动测试：106 项全部通过；视觉定向测试 14 项全部通过。
- 全套测试前后正式数据库修改时间完全不变。

## 性能边界

当前 CPU 对单个素材进行三帧 Florence 描述约需 55 秒，明显不是即时操作。正式 Windows 界面应显示逐素材、逐帧进度，并在后续提供“快速登记”和“后台深度分析”两阶段体验；不能用减少风险覆盖换取虚假的快速完成。
